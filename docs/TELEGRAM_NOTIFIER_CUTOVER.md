# Перенос Telegram-notifier из CRM в Seller

## Граница ответственности

Seller создаёт и хранит состояния выдачи, поэтому только Seller определяет, когда заказ требует оператора. CRM после переключения не читает БД Seller и не отправляет уведомления по этим заказам.

Telegram-аккаунт бота, token и существующие чаты сохраняются. Переносится процесс, который читает состояния и вызывает Bot API.

## Защита от потерь и дублей

- событие создаётся транзакционно вместе с изменением `order_fulfillments`;
- получатель всегда имеет `workspace_id`;
- одна пара event/recipient создаётся ровно один раз;
- сетевой вызов выполняется вне транзакции заказа;
- временная ошибка сохраняется как `retry` с exponential backoff;
- после падения процесса истёкший lease возвращается в очередь;
- старые fulfillment не создают события при применении миграции;
- Telegram update offset переносится из CRM, чтобы старые команды не проигрались повторно.

## Порядок production-cutover

1. Создать резервную копию PostgreSQL Seller.
2. Развернуть код и применить миграцию `20260827_05_telegram_notifications.sql`.
3. Импортировать существующие chat ID в правильный workspace и актуальный update offset из CRM.
4. Передать тот же bot token в `SELLER_TELEGRAM_BOT_TOKEN`, оставив `SELLER_TELEGRAM_NOTIFICATIONS_ENABLED=false`.
5. Убедиться, что таблицы очереди пусты либо содержат только события, возникшие после миграции.
6. Остановить `gamesales-ozon-notifier`. Два consumer `getUpdates` одновременно не запускаются.
7. Включить `SELLER_TELEGRAM_NOTIFICATIONS_ENABLED=true` и запустить контейнер `notifier`.
8. Проверить `getMe`, логи контейнера, состояние delivery-очереди и тестовый переход в `manual_required`.
9. После доставки проверить переход `sent` и отдельное уведомление `resolved` при решении проблемы.

## Будущее сетевое подключение

По умолчанию используется `https://api.telegram.org`. Настройка `SELLER_TELEGRAM_HTTPS_PROXY` передаётся как стандартный `HTTPS_PROXY` только контейнеру `notifier`; API, worker и PostgreSQL через него не работают. `SELLER_TELEGRAM_API_BASE` позволяет подключить контролируемый relay или локальный Bot API. Прокси не должен менять токен, логировать тела сообщений или обходить долговечную очередь Seller.
