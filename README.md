# HomTech Seller

Самостоятельный кабинет продавца для подключения Ozon и Яндекс Маркета.

На первом релизе продукт работает в режиме **read-only**: получает и сохраняет локальный снимок подключений, каталога и заказов. Он не отправляет коды, не подтверждает доставку и не меняет данные в маркетплейсах.

## Границы продукта

- отдельный репозиторий, VM и PostgreSQL;
- отдельный ключ шифрования токенов маркетплейсов;
- собственные пользователи, организации и роли;
- связь с CRM в будущем — только через SSO/API, без общего доступа к базам данных.

Подробнее: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Локальный запуск инфраструктуры

```bash
cp .env.example .env
docker compose up -d postgres
docker compose --profile maintenance run --rm migrate
docker compose up -d api worker web
curl http://127.0.0.1:18080/health
```

PostgreSQL намеренно не публикуется в интернет: он слушает только loopback-порт VM для SSH-туннеля. В production API также будет доступен только через reverse proxy.

Для локального запуска API и Vue с PostgreSQL на VM используйте [docs/LOCAL_DEVELOPMENT.md](docs/LOCAL_DEVELOPMENT.md). База на VM открывается только в SSH-туннеле.

## Версия

Текущая версия Seller задаётся в `web/package.json`, отображается в правом нижнем углу интерфейса и обновляется при каждом релизе. Версию FastAPI в `api/app.py` меняем одновременно; автоматический тест проверяет, что значения совпадают.

## Авторизация

Seller пока использует самостоятельные email/пароль аккаунты. Первая регистрация создаёт организацию (workspace), владельца и изолированную область данных. Тарифы и подключения маркетплейсов будут принадлежать workspace, а не персональному пользователю.

SSO с CRM будет добавлен позже через `auth_subject`; он заменит способ входа, не перемещая магазины, заказы или подписки.

## Состояние первого этапа

Seller уже содержит самостоятельную авторизацию, подключения Ozon и Яндекс Маркета, локальные снимки каталога и заказов. Синхронизация ставится в долговечную PostgreSQL-очередь и выполняется отдельным worker-процессом с защитой от параллельной работы одного магазина и повторными попытками при временных сбоях.
